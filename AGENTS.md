## Current interface baseline (v1.1.0)
- `N` defaults to 1 and supports 1–64 separated `sram<i>` interfaces; no packed SRAM port arrays.
- Each port has an independent `W<i>` parameter (any integer 1–512, including non-powers of two) and `BE<i>_EN` switch. These are elaboration-time settings, not runtime CSR settings.
- `PORT_SIZE` and backdoor addresses use 32-bit lane units. Use the lane-group formulas in `INTEGRATION_GUIDE.md` for other frontend widths.
- Core `ID` = `0xADE50110`; VCU1525 `BOARD_ID` = `0xB0AD0110`. Catalog VLNV = `rismd.cn:hades:hades_sram:1.1`; vendor = `rismd.cn`.
- `ip/hades_sram_1.0/` is generated output, not maintained source. XGUI source is `ip/xgui/hades_sram_v1_1.tcl`.
- Product Guide sources are `docs/hades_sram_product_guide.{md,toml,pdf}` and `docs/images/`. The PDF is a maintained deliverable regenerated by the shared sibling HADES-Doc project.
- Maintained generator/backend sources and `hades_sram_wizard.json` are `tools/`; packaged `tools/` directories are generated copies. The CLI, native launcher, allocation/service layer, and NDJSON protocol share this backend; generated timing is analytical, not implementation signoff.
- Generation defaults to full integration-source copying. Generated RTL and copied core RTL are under `logical/`; analytical HTML/JSON/text/SVG outputs are under `report/`; root `wrapper.f` and full-copy `static_rtl.f` are separate compile filelists. Every physical SRAM port has `constraints/sram<i>_strict.xdc` with explicit I/O delays and no CDC exceptions. The native full-copy checkbox and CLI `--no-full-copy` disable maintained-source copying without changing configuration JSON.
- The maintained native Eclipse UI and reusable `cn.rismd.hades.wizard.modulepreview` bundle are in the sibling `/home/kumon/Projects/HADES-Wizard` project. Do not edit it from HADES-SRAM tasks unless explicitly authorized. Its provider staging, source payload, and Linux/Windows products are generated outputs. The native module preview supports pan/zoom and expandable signal groups, with a synchronized accessible tree.
- Current self-test pattern generation supports only 32/64-bit physical ports; the generator rejects self-test inclusion with other widths.

## Standard commands
- `make -C sim` — run generator and test suite with VCS (default); `SIM=xsim` for Vivado simulator
- `make -C sim lint` — Vivado elaboration gate for both CSR_EN variants
- `make -C sim check_bounds` — static slot-budget assertion spot-checks (T11 preview)
- `make -C sim check_generator` — backend unit/API/CLI/protocol/native-launcher tests plus generated RTL smoke for `SIM`
- `make -C sim check_wizard` — sibling native Eclipse SRAM integration tests and Linux/Windows provider packaging; override `WIZARD=/path/to/HADES-Wizard`
- `make -C sim check_wizard_windows` — actual Windows core/SWT tests plus packaged Automatic/Manual GUI workflows; override `WIZARD`, `WIZARD_POWERSHELL`, or `WIZARD_WINDOWS_PYTHON` as needed
- `make -C sim check_generator_ip` — generated Vivado IP, per-port XDC timing paths, synthesis, wrapper, and fake-host CSR checks; run after packaging
- `./tools/hades-sram-gen <init|validate|analyze|generate|gui|protocol> ...` — shared backend CLI, native launcher, and stdin/stdout protocol; `docs/hades_sram_generator.md` is the user guide
- `vivado -mode batch -source fpga/vcu1525/build.tcl -tclargs SYNC|ASYNC [PCIE|MMCM]` — VCU1525 bitstream (A1)
- `vivado -mode batch -source fpga/vcu1525/host/<script>.tcl -tclargs ...` — board acceptance scripts (A2–A10): a2_init, a4_latency, a5_soak, a6_refresh, a7_dualfreq, a8_config, a9_soak, a10_clock (args in each file header). ASYNC-bitstream legs need env `HADES_SRC_UI_RATIO=3` (MMCM src; the freq monitor counts ui_clk cycles, the divider counts src_clk cycles) and `HADES_LTX=<build/async_MMCM/...ltx>`
- `vivado -mode batch -source ip/package_ip.tcl` — package the Vivado IP and generated documentation/tool payload (catalog-verified)
- `vivado -source ip/open_ip_gui.tcl` — open the hades_sram IP configurator in the Vivado GUI (scratch project `ip/work_gui/`)
- `../HADES-Doc/bin/hades-doc render docs/hades_sram_product_guide.toml` — rebuild the Product Guide PDF from Markdown
- `../HADES-Doc/bin/hades-doc verify docs/hades_sram_product_guide.pdf` — check PDF structure and optionally render page previews

## Design rules (spec §4, do not violate)
- Two clock domains: `ui_clk` (300 MHz) and `port_clk` (100–500 KHz); `CLK_MODE ∈ {SYNC(default), ASYNC}`
- ASYNC CDC only via whitelist in `rtl/hades_sram_cdc.sv` (`hades_sram_sync2`, `hades_sram_qs_bus`, `hades_sram_rst_sync`) — no bare cross-domain wires
- `CSR_EN ∈ {1(default), 0}`: CSR-configurable vs static hard-wired (params `P_*`, incl. flat per-port `P_PORT_BASE`/`P_PORT_SIZE` vectors); both produce the same internal `cfg_t`
- Slot budget static assertion in `hades_sram_top` must pass for any shipped parameter set
- Style: SV-2012, `` `default_nettype none ``, synchronous resets, no latches, 2-process FSMs, `for generate` for port arrays
- XGUI: use `get_guiparamspec` only in `init_gui` and `update_gui_for_PARAM_VALUE.*`; change underlying parameter enablement in `update_PARAM_VALUE.*` with literal `true`/`false`. Do not set parameter enablement in `init_gui`.
- `open_ip_gui.tcl` creates the IP first and defers `start_ip_gui -ip` until GUI startup has completed. Do not start customization during startup and exit before the deferred dialog opens.
- No `TODO/FIXME/XXX` in `rtl/` (spec §7 DoD)
